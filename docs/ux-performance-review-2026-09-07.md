# DKP Registrator 사용감·성능 점검 — 2026-09-07

대상: 로컬 `1.5.1-local.2 → 1.5.1-local.3`. GitHub 배포와 Photo Editor 독립 앱은 이번 범위에 포함하지 않았다.

## 판단

기준 사진과 현재 사진을 나란히 놓고 확대를 연결하는 기본 흐름은 전문 사진 도구의 관행에 부합한다. 임상사진 두 장의 정합·비교라는 목적에는 현재 기능 구성이 충분하다. 지금은 기능 수보다 반복 조회 속도, 사진 표시 면적, 대상과 상태의 명확성이 더 중요하다.

‘업계 표준’ 중 Lightroom/Capture One의 동작은 널리 쓰이는 제품 관행이며, 규격 인증을 의미하지 않는다. 접근성은 W3C 권고를 참고했지만 전체 WCAG 적합성을 인증한 것은 아니다. 실제 경쟁 제품과 속도 대결이나 임상 정합 정확도 연구를 한 것도 아니다.

## 적용한 개선

- 사진·마스크·결과의 압축된 미리보기를 재사용한다. 서버 캐시는 최대 128개/64MiB이며, 브라우저에는 `no-store`로 응답해 임상사진의 영구 디스크 캐시를 요구하지 않는다.
- 원본 이미지 캐시는 기존 4장 제한에 256MiB 상한을 추가했다. 한 장이 상한보다 크더라도 정상 표시하되 캐시에 남기지 않는다.
- 마스크 캐시는 실행 취소 때도 증가하는 세션 revision으로 구분한다. 실행 취소 후 다른 점을 찍어 같은 mask revision 번호를 재사용해도 옛 마스크가 나오지 않는다.
- 결과 캐시는 고유한 정합 결과 ID로 구분한다. 관계없는 작업 변경 때문에 동일 결과를 다시 요청하는 것을 줄이며, 이전 기준·이전 결과는 별도로 보존한다.
- 목록과 상단 기준 슬롯은 256px 썸네일을 사용한다. 작업 화면·SAM 입력·원본 내보내기의 해상도나 비율을 낮추지 않았다.
- 색상 겹침 확대 영역은 두 원본에서 필요한 영역만 잘라 합성한다. 아주 어두운 0/1 픽셀 영역을 0~1 부동소수점 영상으로 잘못 해석하지 않도록 표시용 합성도 수정했다.
- 중첩된 상태 조회를 하나의 진행 요청과 후속 갱신으로 합친다. 서버 연결이 끊기면 상태줄에 표시하고, 다시 연결되면 최신 상태를 조회한다.
- 현재 마스크 대상 화면에 테두리를 표시하고, 새 사진을 읽는 동안 로딩 상태를 표시한다. 이전 이미지/마스크 DOM을 재사용하지 않는 기존 잔상 방지 처리는 유지했다.
- Z 직후 Ctrl+Z 입력은 진행 중인 확정 응답을 기다린 뒤 저장된 마스크를 취소한다. 응답이 늦으면 취소가 초안 닫기로 소비되던 경우를 수정했다. 사진 로딩 표시도 브라우저 디코딩 완료 시점까지 유지한다.
- 집중 보기, 작은 창의 가로형 사진 카드, 줄바꿈을 줄인 도구막대로 사진 표시 면적을 확보했다. 버전 표시는 작은 화면에서도 유지한다.

## 측정과 한계

측정 스크립트: `.unlazy/iteration-3/benchmark.py`. 실제 사용자 사진이나 사용 중인 세션을 건드리지 않고 별도 임시 세션을 사용했다. 같은 4032×3024 합성 JPEG 7장을 넣고, 각 사진에 합성 마스크를 만든 뒤 목록·본문·마스크 API를 사진마다 방문했다. 총 4회 순회, 28회 방문, 84개 응답이다. 동일 PC의 FastAPI TestClient 측정이며 브라우저 렌더링·네트워크·실제 SAM 추론 시간은 포함하지 않는다.

초기 업로드는 앞선 local.2에서 최적화했고, 이번 측정에서는 추가 개선이라고 할 차이가 없다. 이번 개선의 핵심은 반복 보기 비용이다. 원시 기록은 `.unlazy/iteration-3/before.json`, `after.json`에 있다. 수치는 사진 크기·형식·저장 위치·컴퓨터에 따라 달라진다.

서버의 캐시 상한은 앱 전체 메모리 상한이 아니다. 원본 정합 결과와 실행 취소 이력, SAM 모델 자체의 메모리는 별도다. 수백 장의 고해상도 결과를 장기간 유지하는 작업까지 충분하다고 단정하지 않는다. 이번 검증은 7장 반복 조회와 30장 브라우저 작업 흐름에 초점을 맞췄다. Mac의 실기기 체감 속도도 이번 Windows 로컬 작업에서 측정하지 않았다.

검증 결과와 실행 중인 버전은 `.unlazy/iteration-3/GATES.md` 및 `live.json`에 기록한다. 임상 정합 알고리즘·비율 보존 정책은 유지한다.

실제 SAM2도 별도 합성 사진 A/B/A/A로 확인했다. 이미지 특징 계산은 두 번, 다시 방문한 A의 미리보기는 동일했고 Z 확정 뒤 저장된 마스크도 확인했다. 이 PC의 CUDA에서 최초 호출 약 1.526초, A 재방문 약 12/11ms였다. 모델 초기화가 포함된 최초 호출과 반복 호출은 구분해야 한다. 선택적 SAM2 C 확장 후처리 모듈이 없는 기존 환경 경고는 남아 있으며 이번 작업에서 패키지 설치를 변경하지 않았다.
