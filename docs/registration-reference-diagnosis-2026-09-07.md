# 소구치에 치우친 정합: 코드 진단과 개선안

범위: 사용자 사진은 제공되지 않아 해당 사례의 원인을 확정하지 않는다. 현재 코드의 실제 처리와 합성 대응점 재현으로 확인한 한계를 설명한다. 이번 변경은 와이프 조작 복구와 100% 버튼 제거이며, 정합 알고리즘의 변경은 아래 제안 단계다.

## 현재 처리

1. SAM2로 선택·확정한 개체들은 사진별로 합쳐져 하나의 마스크가 된다. 전치와 소구치를 서로 다른 기준 구조물로 식별하거나, 고정상 전치와 이동상 전치를 짝지어 전달하지 않는다 (`webapp/server.py:_union_mask`, `_run_registration`). 고정상과 이동상 양쪽에 마스크가 있어야 마스크 정합을 사용한다. 한쪽만 있으면 양쪽 모두 전체 영역 마스크로 대체한다.
2. 마스크 주변을 잘라 명암을 보정하고, 기본 320→480→640px 피라미드에서 LoFTR로 대응점을 찾는다 (`register.py:register_test`).
3. 각 단계에서 전체 영상 매칭과 마스크를 강조한 매칭을 합친다. 마스크 필터는 후자에만 적용한다. 따라서 선택 밖의 대응점도 포함되고, 두 경로가 찾은 같은 부근의 대응점을 중복 제거하거나 구조물별로 균등하게 배분하지 않는다 (`_match_at_level`).
4. RANSAC으로 가장 일관적인 대응점 집합을 선택한다. 최종 변환은 회전·이동·균일 배율만 허용한다. affine은 실패 시 대응점 후보 집합을 찾는 데만 쓰고, 출력은 다시 similarity로 맞춘다 (`_run_gate`).
5. 다음 단계는 이전 변환으로 미리 맞춘 영상에서 더 보정한다. 이때 이동 마스크를 실제로 변환하지 않고 고정 마스크를 대신 사용한다. 초기 오차로 전치가 고정 마스크 밖에 있으면 그 부분의 masked 매칭이 약해질 가능성이 있다. 전체 매칭도 함께 있어 항상 제외된다고 단정할 수는 없다.
6. 사용자가 찍은 대응점은 최종 단계에서 자동 대응점과 함께 가중 최소제곱으로 다시 맞춘다. 수동 점에 큰 비중을 주지만 반드시 정확히 통과시키는 강제 제약은 아니다.
7. 품질 판정은 선택된 inlier의 오차·개수·분포·배율·회전을 본다. 제외된 전치 대응점의 오차는 중앙값/90분위 오차에 들어가지 않는다. 구조물별 지원 여부나 수술 부위의 정합 정확도는 별도로 검사하지 않는다 (`transform.py:quality_gate_similarity`).

## 확인한 편향

`.unlazy/wipe-diagnosis/reproduce.py`는 영상/SAM 추론이 아닌 **통제된 합성 대응점** 실험이다. 소구치 역할 120점과 전치 역할 12점을 떨어진 두 영역에 배치하고, 소구치는 공통 이동으로 맞지만 전치는 거기에 세로 22px 차이를 추가했다. 실제 `_run_gate` 호출 결과:

| 항목 | 결과 |
|---|---:|
| 채택된 소구치 점 | 120/120 |
| 채택된 전치 점 | 0/12 |
| 소구치 오차 중앙값 | 0px |
| 전치 오차 중앙값 | 22px |
| 앱이 보고하는 inlier 중앙 오차 | 0px |
| 품질 판정 | pass |

한쪽만 맞는데도 전체가 좋은 것처럼 판정될 수 있다는 증거다. 22px는 이 실험의 좌표 단위이며 환자 사진의 실제 오차나 mm가 아니다. 환자 사례에서 소구치의 대응점이 실제로 많았는지, 전치 매칭이 틀렸는지, 촬영 기하가 달랐는지는 원래 이미지와 매칭 분포를 확인해야 한다.

## 기하학적 한계도 구분해야 한다

소구치를 중심으로 작은 회전 오차가 있으면 멀리 있는 전치에서 큰 수직 오차가 나타날 수 있다. 이는 두 영역을 함께 사용하는 추정으로 개선할 여지가 있다.

반면 3차원 표면을 서로 다른 위치·각도에서 촬영하면 깊이에 따라 상대적 이동이 달라질 수 있다. 하나의 2차원 회전·균일 배율·이동만으로 양쪽을 동시에 맞출 수 없는 경우도 있다. ‘같은 악궁의 사진이면 정확히 similarity 관계’라는 기존 config 주석은 일반적인 촬영 기하에 대한 보장으로 받아들이면 안 된다. 카메라 투영 및 평면 변환의 조건은 [OpenCV 카메라 모델](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html), [homography 설명](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)을 참고했다.

이때 비율을 늘이거나 부분적으로 휘어서 맞추면 사용자 제약을 위반하고 비교하려는 차이도 바뀔 수 있다. 이번 제안은 비율 보존을 유지한다.

## 권장 구현 순서

### 1. 구조물별 매칭과 실패 감지

- 확정 마스크의 개체 ID를 엔진까지 보존하고 기준/이동 사이의 대응 구조물을 짝짓는다. 단순 연결 요소만으로 분리하면 붙은 치아나 끊어진 마스크를 오인할 수 있으므로, 저장된 선택 개체와 필요 시 사용자 확인을 이용한다.
- 구조물별 유효 대응점 개수, 공간 분포, 잔차와 최대 편중을 표시한다. 한 구조물만 지원되고 다른 선택 구조물이 설명되지 않으면 ‘정합 완료/통과’로 판정하지 않고 ‘전치 기준 확인 필요’처럼 원인을 드러낸다.
- 전치/소구치별 색을 달리한 매칭점 표시를 제공한다. 원래 제외된 점도 별도로 볼 수 있어야 중앙 오차가 작아지는 이유를 알 수 있다.

### 2. 추정 자체를 여러 구조물에 균형 있게 만들기

- global/masked 중복 대응점을 제거하고, 한 구조물의 좁은 부분에서 점이 과도하게 모이지 않도록 공간 샘플링한다.
- 선택된 구조물의 각 총 가중치를 제한·정규화한다. 개별 점은 신뢰도로 가중하되 큰 구조물/점이 많은 구조물이 결과를 독점하지 못하게 한다.
- **RANSAC 이후 가중치만 바꾸는 것으로는 부족하다.** 이미 제외된 전치가 복구되지 않으므로 후보 생성·선택부터 여러 구조물의 지원을 요구한다. 전치 매칭 자체가 불충분하면 억지로 같은 비중을 주지 말고 대응점 요청으로 넘긴다.
- 피라미드의 이동 마스크는 실제 누적 변환으로 옮긴다. 초기 오차 때문에 중요한 부위가 탈락하지 않는지 별도로 검사한다.

### 3. 수동 기준점 우선 경로

- 자동정합이 한쪽으로 치우치면, 무치악 부위 양쪽의 변하지 않은 식별 가능한 지점에 대응점을 분산해서 지정한다.
- 기존은 자동정합 뒤 보조점 재적합이므로, 별도의 ‘기준점 우선’ 경로에서는 이 점들로 먼저 similarity를 구하고 자동 매칭이 이를 무시하지 못하게 제한하는 방향을 권한다.
- 두 쌍은 변환을 정할 수 있지만 두 점이 정확히 맞는 것만으로 전체 정합을 검증할 수 없다. 가능하면 3쌍 이상을 분산하고 각 점의 잔차·교차 검증을 보여준다. 점이 서로 모순되면 원근/식별 오류 가능성을 표시하며, 임의로 늘여 맞추지 않는다.

### 4. 수술 부위는 비교 대상, 안정 구조물은 정합 기준으로 구분

- 무치악 수술 부위는 관심 영역으로 표시하되, 변화를 관찰하려는 조직을 강제로 일치시키는 목표로 사용하지 않는다.
- 주변 안정 구조물들이 함께 지지하는 변환을 사용한다. 주변 치아가 맞는다는 사실만으로 관심 영역의 실제 오차가 0이라고 주장하지 않는다.
- 양쪽 기준을 동시에 만족할 수 없으면 ‘촬영 각도 차이 또는 대응점 불일치로 전역 정합 한계’로 보고, 국소 결과로 명시하거나 더 유사한 촬영 조건/다른 영상 자료를 검토한다.

추천은 **1→2를 우선 적용하고 3을 보정 수단으로 연결**하는 것이다. 4는 ‘어디를 기준으로 맞추고 어디의 변화를 볼지’를 분리하는 UI 원칙이다.

## 구현 후 수용 기준 제안

- 소구치 120점/전치 12점처럼 불균형한 합성 입력에서도 한쪽만 지지하는 변환을 무경고 pass로 내보내지 않는다.
- 여러 구조물의 올바른 대응이 존재하는 경우 양쪽 잔차가 개선되는지, 잘못된 전치 매칭을 넣었을 때는 오히려 실패를 검출하는지 확인한다.
- 원근 차이 때문에 similarity로 해결할 수 없는 입력은 비율을 보존하고 정합 한계를 알린다.
- 최종 표시·다운로드·수동 조정·실행 취소·이전 기준 보존이 동일한 비율 보존 변환을 사용한다.
- 실제 사례는 사진과 매칭 로그로 별도 검증한다. 합성 재현만으로 임상 부위의 정확도를 검증했다고 보고하지 않는다.
