# 대응점 기반 슬라이딩 윈도우 수정 계획

상태: 2026-09-07 구현 및 로컬 검증 완료. 실행 버전 1.5.1-local.6, 포트 8795. 아래는 승인된 계획이며 실제 채택값과 검증 범위는 마지막 절에 기록한다.

사용자 의도: 피라미드 각 단계에서 원본 좌표로 모은 대응점 주변을, 겹쳐 이동할 수 있고 양쪽 사진의 배율에 따라 크기가 달라지는 창으로 재매칭한다. 마스크 없는 기본 정합에서 작동하고 사용자 마스크/앵커 지정은 요구하지 않는다. 특정 해부학적 부위는 가정하지 않는다.

## 근거와 적용 범위

- [COTR 논문 §3.3](https://arxiv.org/html/2103.14167v1): 추정 대응 위치 주변의 원본 크롭을 반복 확대하고 영상 사이의 크기 차이를 보상한다. [공식 refinement_task.py](https://github.com/ubc-vision/COTR/blob/master/COTR/inference/refinement_task.py)도 양쪽 스케일을 별도로 정하고, 갱신된 대응 위치에서 다음 패치를 만든다.
- [PATS 논문 §3.3](https://arxiv.org/html/2303.07700v3): 대응 창의 크기를 추정 배율로 연결하고, 경계 근처 대응 누락을 줄이기 위해 창을 확장하며, 겹침에서 나온 중복을 제거한다. PATS 자체는 초기 패치 격자를 사용한다. 고정 격자를 전혀 쓰지 않는 논문이라는 뜻은 아니다.
- [ASpanFormer 공식 설명](https://aspanformer.github.io/): 추정 대응 위치와 불확실성을 이용해 특징 탐색 범위를 조절한다. 원본 크롭 슬라이딩 구현 자체와는 구분한다.

공인된 치과 정합 표준이나 특정 창 크기/겹침률에 대한 업계 공통 규격은 확인하지 않았다. 기존 LoFTR에 적용할 설계는 이 연구들의 배율 보정·지역 정밀화·겹침 처리 원칙을 참고한 구현안이며, 논문의 학습 모델을 그대로 도입하거나 동등한 성능을 보장하는 것은 아니다.

## 현재 코드에서 바꿀 부분

`regional_matching.py`의 격자는 `seed_regions`의 시작 영역 선택뿐 아니라 `bounded_pool`의 점 제한, `_fit`의 가중치, `validate_candidate`의 검증 구역에도 사용된다. 네 군데를 함께 바꾼다. 현재 `crop_input`은 각 이미지 장변의 36% 이상을 보며 양쪽 창 크기의 비율을 명시적으로 연결하지 않는다. 가장자리에서는 단순 잘라내기를 한다. 이 부분도 교체한다.

## 처리 흐름

1. **격자와 무관한 시작점 선정.** 원본 좌표 대응점을 모으고 중복을 제거한다. 양쪽 영상에서의 실제 이웃 거리와 지역 기하 일관성을 이용해 후보를 고른다. 드문 유효 대응을 고정 칸의 점 수 부족 때문에 버리지 않는다. 전역 RANSAC에 포함됐는지만으로 시작 후보를 결정하지 않는다.
2. **겹치는 슬라이딩 후보.** 대응점 주변에서 기준 창 중심을 여러 위치로 이동시킨다. 초기 실험은 1024×1024 정사각형 사진 기준 약 220×220 창, 창 폭의 약 50% 이동 간격으로 한다. 실제 이미지 크기에 비례해 환산하고, 대응점이 없는 전체 배경까지 전수 추론하지 않는다. 대응 묶음의 경계를 덜 자르고 새로운 영역을 더 포함하는 창을 우선한다.
3. **배율을 반영한 양쪽 창.** 시작 대응들의 지역 similarity로 고정상→이동상 배율과 대응 중심을 추정한다. 이동상에서 같은 대상이 1.2배 크면 고정상 220 창에 이동상 약 264 창을 대응시킨다. 원본 픽셀 좌표에서 계산하며 파일 해상도 비율을 대상 배율로 대신하지 않는다. 지역 배율이 불안정하면 전역 배율을 보조값으로 사용하고 위치 오차에 맞춰 탐색 여유를 늘린다. 전역 추정값으로 가짜 대응점을 만들지 않는다.
4. **가장자리와 전처리.** 창 크기를 유지할 수 있도록 중심을 안쪽으로 이동하고 상대 영상의 중심 관계를 함께 갱신한다. 불가피한 영역은 패딩하고 유효 픽셀 범위를 추적하여 패딩에서 생긴 매칭을 제외한다. 양쪽 입력의 대상 크기를 맞추는 리사이즈는 균일 배율만 사용한다. 정사각형 강제 늘이기를 사용하지 않는다.
5. **실제 재매칭과 제한된 후속 탐색.** 원본 크롭을 LoFTR에 넣고 대응점을 원본 좌표로 돌린다. 결과가 창 경계에 몰렸으면 인접 창으로 옮기고, 안정된 부분은 필요할 때 더 작은 창으로 재탐색한다. 위치가 계속 흔들리거나 추가 공간 범위/독립 대응이 늘지 않으면 중단한다. 창 겹침만으로 무조건 추론 횟수를 늘리지 않는다.
6. **격자 없는 중복·쏠림 처리.** 양쪽 창의 겹침과 포함하는 대응점의 중복을 함께 비교하여 거의 같은 후보 창을 통합한다. 점은 양쪽 끝점 거리로 중복 제거한다. 변환 적합에는 연속적인 이웃 밀도 기반 가중치를 사용하여 같은 부위의 반복 관측이 독점하지 않게 한다. 고정 16칸별 상한은 제거한다.
7. **검증과 출력.** 서로 떨어진 실제 검증점 주변을 검증 영역으로 잡고 고정 격자 구역 판정을 제거한다. 전역·지역 검증점을 적합에서 제외하고, 겹치는 창을 통한 재유입도 막는다. 별도 창에서 다시 관측한 대응의 일관성과 영역별 오차를 비교한다. 최종 출력은 전체 사진에 하나의 similarity만 적용하며, 검증 부족·악화 시 이전 전역 결과를 보존한다.

220픽셀·50%는 사용자 설명을 바탕으로 한 실험 시작값이다. 연구에서 정해진 표준값이 아니다. 1024는 예시 좌표계이며 원본을 반드시 1024로 먼저 축소한다는 뜻이 아니다. 220픽셀 크롭을 640으로 키운다고 실제 원본 정보가 더 생기지는 않는다.

## 실행 비용과 UI

UI 선택이나 팝업을 추가하지 않고 무마스크 일반 정합에 적용한다. 크롭 후보 생성과 실제 LoFTR 추론은 분리한다. 많은 후보를 싸게 비교한 뒤 필요한 후보만 추론한다. 우선 4쌍과 6–8쌍 예산을 비교하고, 총 입력 픽셀·추론 횟수·추론 사이 시간 제한을 함께 적용한다. 방향 자동 탐색을 사용하는 경우에도 지역 재탐색 예산을 사진 쌍 단위로 공유하는 설계를 검증한다. SAM/사용자 앵커 상태는 생성하거나 변경하지 않는다.

## 구현 순서 및 채택 기준

1. 격자 없는 시작점/창 후보/배율/경계 좌표 계산을 독립적으로 구현·검증한다.
2. 창 선택과 대응점 통합에 연결한 뒤 밀도 가중치와 검증 영역까지 교체한다.
3. 기존 고정 격자 방식과 동일 사진·모델·추론 예산으로 비교하고, 마지막에 추가 예산의 효과를 별도로 측정한다.

필수 비교 사례: 격자 경계에 걸친 대상, 영상 모서리, 대상 배율 0.7/1.0/1.3배, 파일 해상도가 다른 동일 장면, 작은 유효 대응 묶음, 반복 무늬, 부분 겹침, 잘못된 초기 매칭, 대응 없음. 배율 수치는 알고리즘 실험 조건이며 임상 허용범위가 아니다.

지표: 알려진 변환 또는 수동 검증점의 분산 위치 오차, 지원되는 공간 범위, 오정합 채택률, 전체 처리시간 중앙값/상위 95%, 최대 메모리. 실제 크롭 범위·원본 좌표 복원·추론 횟수도 기록한다. 순수한 점 수 증가나 합성 한 쌍의 개선만으로 채택하지 않는다.

## 실제 구현과 검증 범위

- `sliding_windows.py`에 대응점 중심 후보, 약 22% 창 크기, 50% 이동 간격, 지역 similarity 배율 연결, 경계 이동/패딩, 최대 한 세대 후속 이동·확대를 구현했다. 지역 배율을 신뢰할 수 없는 후보는 건너뛰고 전역 결과를 보존한다. 계획의 불확실한 지역에 대한 전역 배율 대체는 사용하지 않는 보수적 선택이다.
- `regional_matching.py`의 고정 구역 선정·구역별 상한·구역 가중치·구역 검증을 실제 점 거리, 밀도 및 점 중심 이웃으로 교체했다. 중복점 검색용 공간 해시는 남지만 창 선정이나 구역 할당에는 쓰지 않는다.
- 전역/크롭 점의 정밀도 차이를 적합 가중치에 반영한다. 통합점 적합과 지역점 적합을 각각 검증하며, 전역 및 지역 보류점 검증을 모두 통과해야 채택한다. 최종 변환은 하나의 similarity다.
- 기본 추가 추론은 사진 쌍당 최대 6회다. 방향 탐색에서도 예산을 공유하며 픽셀 수 제한과 추론 사이 6초 제한을 둔다. 실행 중인 단일 추론을 강제 종료하는 시간 제한은 아니다.
- 좌표·경계·실제 크롭 배율·중복·밀집 분포·후속 창·방향 공유 예산·API·기존 기능을 포함한 80개 자동 검사가 통과했다. 창 기하 검사는 0.7/1.0/1.3배, 실제 LoFTR 합성 비교는 0.75/1.0/1.3배 및 파일 해상도 차이와 가로 사진을 포함한다.
- 동일 모델/전역 대응으로 기존 4회, 새 4회, 새 6회를 비교했다. 5사례 최대 위치 오차의 중앙값은 각각 2.11 / 1.64 / 1.13px였다. 새 6회는 모든 사례에서 기존 4회보다 낮았다. 시간은 기기·입력에 의존하며 약 0.3초 증가했다. 측정 원본은 `.unlazy/sliding-windows/model-evidence.json`이다.
- 실제 환자 사진의 수동 검증점 정답 또는 임상 오정합률을 측정한 결과는 아니다. 반복 구조가 다른 대상을 일관되게 가리키는 경우와 관점 차이로 하나의 similarity로 표현할 수 없는 경우의 해결을 보장하지 않는다.
- 기존 8794 창의 사진과 결과를 유지하고 새 8795 창을 열었다. 원래 바로가기의 새 빌드 탐색도 검사한다. GitHub 배포나 실행파일 패키징은 이번 범위에 포함하지 않는다.
