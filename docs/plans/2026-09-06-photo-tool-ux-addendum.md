# 사진 비교·편집 도구 조사에 따른 작업대 UX 개정안

작성: 2026-09-06. [기존 구현 계획](2026-09-06-registration-ux-plan.md)의 화면 구성과 이미지 불러오기·기준 지정 부분을 이 문서로 개정한다. 단축키, 비율 보존, 앵커, Photo Editor 통합, 실행취소 요구는 유지한다. 공식 문서 조사에 따른 제안이며 실제 앱 사용성 측정 결과는 아니다.

제품 조사에서 얻은 공통점은 **사진 집합 중심의 탐색, 비교 기준 고정, 현재 사진과 선택 집합 구분, 큰 미리보기, 복원 가능한 편집**이다. 특정 버튼 위치나 단축키까지 공통으로 강제하는 표준은 아니다. 아래 내용은 이 관행을 임상사진 정합에 맞게 적용한 설계 결정이다.

## 2. 가장 큰 변경 — 하나의 사진 집합과 하나의 작업대

### 처음 시작

1. 시작 화면과 상단의 **사진 추가**로 여러 장을 한 번에 선택한다. 드래그앤드롭도 같은 경로를 쓴다.
2. 처음 성공적으로 불러온 순서의 첫 사진이 기본 Fixed, 나머지는 Moving이다. 파일 선택 창의 클릭 순서가 FileList 순서와 같다고 가정하지 않는다. 실제 적용한 순서를 목록으로 보여 준다.
3. 첫 로딩 후 `DSC_0300을 기준으로 설정했습니다 [변경]`을 표시한다.
4. 기준과 첫 Moving이 나란히 보이고 즉시 정합할 수 있다. SAM2 마스크 입력을 필수 단계로 보이게 하지 않는다.
5. 사진이 1장뿐이면 그 사진을 기준으로 편집할 수 있고, 정합 버튼에는 `비교할 사진을 추가하세요`를 표시한다.
6. 이후 사진 추가는 기존 기준을 바꾸지 않고 목록에 추가한다. 손상된 첫 파일은 제외하고 성공한 첫 파일을 기준으로 하며 제외 파일과 이유를 표시한다.

### 기준 바꾸기

- 어떤 사진이든 목록/사진 메뉴에서 **기준으로 지정**. 현재 사진에도 같은 명령을 제공한다.
- 기존 기준은 일반 작업 사진으로 돌아가며 파일을 재업로드하거나 다시 디코드할 필요가 없다.
- 목록 순서는 바꾸지 않는다. 기준 배지와 기준 패널만 변경한다. 현재 사진이 새 기준이 되면 이전 기준을 오른쪽 작업 사진으로 보여 준다.
- 변경은 취소 가능한 한 작업이다. `기준 변경: DSC_0300 → DSC_0328 [되돌리기]`를 표시한다.
- 원본별 편집값과 마스크는 보존한다. 역할 변경은 이미지 데이터를 지우는 작업이 아니다.
- 앵커는 `(fixed_image_id, moving_image_id)` 쌍에 속한다. A→B 앵커를 C→B 앵커로 자동 사용하지 않는다. 이전 기준을 다시 선택하면 그 기준의 앵커를 복원한다.
- 결과도 기준 사진 ID/편집 revision/입력 상태에 속한다. 새로운 기준 아래에서 예전 결과를 최신 결과로 표시하지 않는다.
- 기준 변경 즉시 정합을 자동 실행하지 않는다. 필요한 대상 수와 **새 기준으로 정합** 버튼을 표시한다.
- 정합 실행 중에는 뷰 탐색이 가능하되 기준 변경은 작업 경계에서 적용한다. 명령에 `남은 작업 중지 후 기준 변경`을 제공해 현재 계산을 강제로 끊지 않는다.
- 새 기준 삭제는 대체 기준 지정과 하나의 작업으로 처리한다. 아무 사진도 남지 않으면 빈 작업대로 복귀한다.

## 3. 작업대 배치

```text
사진 추가       기준: DSC_0300 [기준 편집]                되돌리기   내보내기
──────────────────────────────────────────────────────────────────────────
     작업 도구: 마스크 · 앵커 · 미세조정     보기: 나란히 / 겹치기 / 와이프
┌────────────────────────┐ ┌────────────────────────┐ ┌─────────────────┐
│ 기준 사진              │ │ 현재 사진 / 정합 결과  │ │ 현재 도구만 표시 │
│ 항상 같은 자리에 표시  │ │ 사진만 이전/다음 전환  │ │ 접기 가능        │
│                        │ │                        │ │                 │
└────────────────────────┘ └────────────────────────┘ └─────────────────┘
            확대 연결 · 화면 맞춤 · 100% · 부분 확대
──────────────────────────────────────────────────────────────────────────
사진 목록:  [◆기준] [작업1] [작업2 ◀] [작업3] ...      전체 / 검토 전 / 보정 필요
──────────────────────────────────────────────────────────────────────────
대상: 현재 1장 / 체크 3장     정합                    확인하고 다음 / 선택 저장
```

- 기본 목록은 아래 필름스트립으로 두어 두 비교 사진의 가로 공간을 확보한다. 목록이 긴 작업에서는 왼쪽 목록으로 전환 가능하며 선택을 기억한다.
- 도구를 바꿔도 사진·기준·현재 항목·확대 위치를 유지한다. 버튼으로 창을 계속 새로 띄우지 않는다.
- 편집 도구(사진을 바꿈)와 비교 방식(보기만 바꿈)을 같은 탭 줄에 섞지 않는다. `앵커`와 `와이프`는 서로 배타적인 화면 종류가 아니다.
- 마스크 작업은 한쪽 사진을 크게 하고 기준 참고 패널을 유지한다. 앵커 작업은 반드시 원본/현재 편집본 두 장을 보여 준다. 정합 결과 위에 원본 대응점을 찍게 하지 않는다.
- Fixed 편집을 닫으면 이전 Moving/비교 모드/줌 위치로 돌아온다. 현재 사진이 편집된 것으로 착각하지 않도록 `기준 편집 중`을 명시한다.
- 정합 버튼은 항상 같은 위치에 있다. 검토 도중 버튼이 갑자기 '전체 정합'으로 바뀌지 않는다. 정합 명령과 확인/저장 명령을 분리한다.
- 색상은 중립적인 배경과 하나의 강조색을 사용한다. 이미지에 영향을 줄 수 있는 강한 배경색과 과도한 장식은 줄인다.

## 4. 비교 품질을 실제로 높이는 조작

### 확대 연결과 원본 해상도

- 화면 맞춤, 100%, 포인터 중심 휠 줌, Space+드래그 팬을 모든 캔버스에서 통일한다.
- **확대 연결**을 눈에 보이는 토글로 제공한다. 정합 결과와 동일 Fixed 좌표계에서는 같은 부위를 함께 이동·확대한다.
- 정합 전 원본 두 장은 같은 화면 좌표가 같은 치아 위치가 아닐 수 있다. 각각 위치를 맞춘 다음 배율을 연결할 수 있게 하며 '같은 부위 동기화'라고 과장하지 않는다.
- 부분 확대(Loupe)는 사진 전체를 보면서 한 부위의 모양·경계를 확인할 때 사용한다. 정합된 결과는 기준 좌표로 연동한다.
- 현재 서버의 이미지 미리보기는 최대 1024px이므로, 이를 확대해서 100%라고 표시하지 않는다. 100%/Loupe 진입 시 해당 영역의 원본 해상도 ROI를 요청한다.
- 원본 ROI는 가까운 화면 영역을 캐시하고 동시에 모든 사진의 풀해상도 캔버스를 만들지 않는다. 원본 크기·배율·영역을 요청 키에 포함한다.

### 보정과 비교를 오가는 비용 줄이기

- 기본 흐름은 사진 불러오기 → 정합 → 검토. 잘 안 맞는 사진에서만 마스크나 앵커 보조를 사용한다.
- 실패/오차 안내에서 **앵커 추가**, **마스크 수정**, **방향 자동탐색**, **미세조정**으로 바로 연결한다. 근거 없이 어떤 도구가 반드시 해결한다고 단정하지 않는다.
- 드래그 도중에는 즉시 미리보기, 적용 완료 후 서버 상태와 이력을 갱신한다. 슬라이더 이동마다 재정합하지 않는다.
- 임시 미세조정값은 사진별로 유지한다. 적용 전/후 표시와 명시적 취소로 작업 손실을 막는다.
- 결과 교체 시 이전/현재 결과 비교를 제공한다. 사진 편집의 보정 전후와 정합 결과의 전후를 구분해서 표기한다.

## 5. 연속 검토를 독립 작업으로 만든다

- 자동 정합 상태와 사용자의 검토 상태를 분리한다: `정합 완료`와 `검토함`은 다르다.
- 검토 상태는 `검토 전 / 확인함 / 보정 필요`로 단순화한다. 체크박스는 일괄 처리 선택 상태만 뜻한다.
- **확인하고 다음**: 현재 결과를 확인함으로 표시하고, 현재 검토 집합의 다음 사진으로 이동한다. 기준·비교 방식·동기 확대를 유지한다.
- **보정 필요**: 표시만 하거나 바로 보정 도구로 이동한다. 사진을 삭제하거나 실패 결과를 숨기지 않는다.
- 필터가 바뀌거나 검토 상태 변경으로 현재 사진이 목록에서 빠져도 현재 검토 집합의 다음 ID를 먼저 계산하여 사진을 건너뛰지 않는다.
- `확인한 결과 저장`을 추가하되 사용자가 아직 검토하지 않은 결과의 저장도 명시적으로 선택할 수 있게 한다. 강제 승인 단계로 만들지 않는다.
- 기준·마스크·앵커·편집이 바뀌어 결과가 달라지면 그 결과의 이전 '확인함'을 새 결과에 승계하지 않는다.
- 다음/이전 사진의 축소 미리보기를 미리 읽되 화면을 자동으로 이동시키지 않는다.

## 6. 기능 우선순위와 뺄 것

| 우선순위 | 기능 | 이유 |
|---|---|---|
| P0 | 통합 사진 추가, 첫 사진 기본 기준, 중간 기준 변경/취소 | 사용자 지정·초기 진입을 단순화 |
| P0 | 한 작업대, 기준·활성·체크 분리, 선택 정합 후 정확한 결과 | 현재 불편의 직접 원인 제거 |

| P1 | 확대 연결, 100% 원본 ROI, 부분 확대 | 작은 경계를 실제 해상도로 검토 |
| P1 | 확인하고 다음, 보정 필요 필터, 검토한 결과 저장 | 수십 장을 반복 조작 없이 처리 |
| P1 | Photo Editor 폴더/사진 한 장 진입 분리 | 별도 확정된 요구 |
| P2 | 여러 사진 한눈에 보기(2~4장), 키보드 조작 최적화 | 기준 후보를 빠르게 고르는 데 도움 |
| P2 | 앱 재시작 후 작업 복구 | 긴 작업 보호. 현재 세션 삭제 구조 변경 필요 |

이번에 넣지 않을 것: 3D 캐러셀, 다중 별점·색상 분류 체계, 여러 기준을 동시에 사용하는 복잡한 정합 그래프, 자유변형, 대형 사진 카탈로그 관리. 제품 관행을 참고하되 정합 작업에 직접 도움이 되는 부분만 채택한다.

## 7. 구현 계획에 추가되는 파일/상태/API

- `App.vue`: 별도 Fixed/Moving 업로드 UI 제거. 사진 집합과 `fixedId`를 관리하고 역할은 fixedId와 비교하여 계산.
- `Workspace.vue`, `PhotoBrowser.vue`, `ComparisonViewport.vue`, `ContextTools.vue`: 전체 배치·목록·보기·도구를 나눈다. 단순 버튼마다 새 추상화 계층을 만들지 않는다.
- `viewstate.ts`: activeId, checkedIds, fixedId, tool, comparisonMode, viewports, reviewQueue를 구분. 도구 전환으로 뷰를 초기화하지 않는다.
- `webapp/session_state.py`: fixed 변경 이력, `(fixedId,movingId)` 앵커 세트, 결과별 기준 revision 및 reviewStatus.
- POST `/api/upload`: role을 요구하지 않는 배치 입력을 기본으로 하고 입력 순서에 따른 성공 ID 반환. 기존 role API는 이행 중 호환 경로로만 유지.
- POST `/api/fixed`: `{image_id, base_revision}`. 기준 변경, 역할 전환, 관련 결과 조회 기준 변경을 하나의 상태 변경으로 수행.
- GET `/api/image/{id}/region`: 현재 revision의 원본 해상도 ROI. 범위·크기 제한과 취소 가능한 요청 처리. 결과 ROI도 계산 당시 기준 revision과 같은 좌표 사용.
- POST `/api/result/{id}/review`: 해당 result ID/버전에 대한 검토 상태. 이미 교체된 result에 대한 늦은 요청은 거절.
- 선택/업로드/기준 변경을 먼저 구현하고 기존 계획의 이력·앵커·편집 작업을 그 상태 모델에 연결한다. UI 정리를 맨 마지막 장식 작업으로 미루지 않는다.

## 8. 성공을 확인하는 사용자 시나리오

1. 여러 사진 한 번 선택 → 첫 성공 사진이 기준 → 나머지 사진 즉시 정합 가능.
2. 5번을 기준으로 지정 → 기존 기준이 Moving으로 전환 → 마스크·편집 유지 → undo로 이전 기준 복원.
3. 기준 A로 작업한 앵커/결과가 기준 B에서 잘못 적용되지 않고, A로 돌아가면 해당 상태를 다시 찾을 수 있음.
4. 5번만 정합한 뒤 5번 결과가 표시되고, 도중에 8번으로 이동했다면 8번 유지.
5. 확인하고 다음을 반복하여 정해진 집합을 빠짐없이 검토. 비교 방식과 확대 위치가 유지됨.
6. 체크 3장, 활성 1장, 기준 1장의 표시가 구분되고 버튼 대상이 예측 가능함.
7. 100%에서 축소 JPEG가 아니라 원본 ROI가 보임. 원본 표식 이미지로 픽셀 대응 검증.
8. 정합 전 두 사진의 개별 팬·연결 줌, 정합 후 기준 좌표 동기 팬이 각각 올바르게 작동.
9. 사진 30장 수준의 목록에서 썸네일/다음 사진 준비가 작업 클릭을 막지 않음. 실제 지연과 메모리를 측정해 보고하며 현재 성능 수치를 미리 주장하지 않음.
10. 1366×768, 1920×1080 및 화면 배율 125/150%에서 핵심 버튼·기준 표시·현재 도구가 잘리지 않음.

## 9. 화면 예시의 범위

`registration-workspace.html`은 배치와 사진 탐색, 기준 변경, 도구 진입, 확인하고 다음 흐름을 보여 주는 대화용 시안이다. 실제 사진은 넣지 않았고 정합·사진 편집 엔진은 실행하지 않는다. 시안의 단순 작업 전환 버튼은 구현 시 이 문서의 독립된 '편집 도구'와 '보기 방식' 제어로 세분화한다.
