# 대응 영역 크롭 재매칭 제안

조사일: 2026-09-07. 코드 확인 및 문헌 조사에 따른 제안이며, 이번 조사에서 실행 코드나 실행 중인 서버는 변경하지 않았다.

## 현재 구현과 제안의 차이

현재 `config.py`와 `register.py::register_test`는 작업 영역을 320 → 480 → 640 해상도로 매칭한다. 앞 단계 변환으로 이동상을 미리 정렬한 뒤 다음 단계에서 보정하며, 최종적으로 마지막 성공 단계의 대응점과 인라이어를 사용한다. 앞 단계 점을 원본 좌표의 공통 저장소에 누적하거나, 여러 성공 영역을 원본에서 별도로 크롭해 재매칭하지는 않는다.

`webapp/server.py::_run_registration`에서는 양쪽 마스크가 모두 없으면 전체 이미지 마스크를 사용한다. 따라서 SAM 마스크 없이도 전역 매칭이 실행된다. 다만 사진에 따라 신뢰할 수 있는 대응점이 없을 수도 있다. 전체 정합이 실패한 경우에도 일부 영역에서 유효한 대응 후보가 남을 수 있다.

새 `anchor_recovery.py::recommend_anchors`는 현재 양쪽 선택 마스크를 요구한다. 선택 영역의 합집합을 매칭하고, 지원이 부족한 선택 개체를 추가 탐색하지만, 원본의 대응 영역을 양쪽에서 반복 크롭하는 무마스크 경로는 아니다. 추론 입력도 최대 1024 작업 이미지에서 만들어진다.

LoFTR 자체의 coarse-to-fine 단계는 입력 이미지에서 계산한 세밀한 특징 맵의 작은 창을 이용한다. 앱이 전체 사진을 축소하며 버린 원본 세부 정보를 복구하는 별도 원본 크롭 단계와는 다르다. 예를 들어 폭 6000 사진을 640으로 줄이면 폭 600인 영역은 약 64픽셀이다. 원본의 그 영역을 따로 입력하면 더 많은 실제 픽셀 정보를 이용할 수 있다. 이는 해상도 설명이며 성능 측정 결과가 아니다.

## 조사 근거

치과 사진 정합의 공인 표준 알고리즘이라는 의미가 아니라, 일반 영상 매칭에서 연구된 접근과 실용 도구의 기능을 구분해 비교했다.

| 근거 | 확인한 접근 | 이 앱에 적용할 의미 |
|---|---|---|
| [LoFTR, CVPR 2021](https://zju3dv.github.io/loftr/) | 거친 대응을 찾은 뒤 세밀한 특징 맵의 지역 창에서 위치 보정 | 기존 내부 보정과 외부 원본 크롭을 구분해야 함 |
| [COTR, ICCV 2021](https://arxiv.org/abs/2103.14167) | 추정 대응 위치 주변을 재귀적으로 확대하여 대응 정밀화 | 사용자가 제안한 성공 위치 주변 재탐색과 직접적으로 가까운 개념 |
| [PATS, CVPR 2023](https://arxiv.org/html/2303.07700v3) | 대응 패치를 크롭·리사이즈·세분화하며 재매칭; 경계 여유와 중복 패치 제거 사용 | 양쪽 대응 크롭, 스케일 고려, 겹침 중복 제거가 필요 |
| [Patch2Pix, CVPR 2021](https://openaccess.thecvf.com/content/CVPR2021/html/Zhou_Patch2Pix_Epipolar-Guided_Pixel-Level_Correspondences_CVPR_2021_paper.html) | 패치 대응 제안을 지역적으로 픽셀 위치까지 정밀화하고 신뢰도 예측 | 초기 후보의 정밀화와 미탐색 영역의 발견은 별도로 설계해야 함 |
| [COLMAP 공식 FAQ](https://colmap.github.io/faq.html#increase-number-of-matches-sparse-3d-points) | 대응점 증가를 위한 guided matching 옵션 안내 | 추가 유도 매칭이 실용 도구에도 존재. COLMAP이 같은 크롭 알고리즘을 쓴다는 뜻은 아님 |

COTR·PATS·Patch2Pix는 자체 모델과 학습 방법을 가진 연구다. 아래 제안은 그 설계 아이디어를 참고한 기존 LoFTR 확장이며, 해당 모델을 구현하거나 같은 정확도를 보장한다는 의미가 아니다.

## 권장 처리 흐름

1. **전역 후보 보존.** 피라미드의 각 유효 단계에서 대응점을 원본 좌표로 변환해 저장한다. 단계·크롭 출처와 신뢰도를 함께 보존한다. 우세한 한 영역의 RANSAC에서 제외됐다는 이유만으로 모든 다른 영역 후보를 버리지 않는다. 별도 지역 일관성을 확인한 후보만 재탐색 시작점으로 쓴다.
2. **분산된 시작 영역 선정.** 단순 신뢰도 상위 점 대신 공간적으로 떨어진 대응 묶음을 선정한다. 마스크가 있으면 선택 개체별로 탐색 기회를 배분한다. 마스크가 없으면 사진의 공간 구역과 대응 묶음을 사용한다. 해부학적 이름이나 특정 방향을 우선하지 않는다.
3. **양쪽 원본에서 대응 크롭.** 고정상과 이동상 각각에서 실제 대응 위치 주변을 자른다. 양쪽에서 같은 좌표를 자르거나 이미 정합된 결과 화면을 확대하는 방식이 아니다. 예상 크기 차이는 종횡비를 보존하는 리사이즈와 패딩으로 처리하고, 위치 불확실성을 수용할 주변 여유를 둔다.
4. **지역 재매칭과 통합.** 기존 LoFTR로 패치를 매칭하고 점을 다시 원본 좌표로 환산한다. 양쪽 끝점의 위치를 기준으로 중복을 제거한다. 신뢰도, 지역 기하 일관성, 필요시 양방향 대응 검사를 조합한다. 양방향 일치도 반복 무늬의 오매칭을 완전히 보증하지는 않는다.
5. **쏠림 방지와 탐색 확대.** 같은 크롭에서 나온 밀집 점의 영향력을 제한한다. 탐색 예산 일부는 점이 부족한 주변의 겹치는 영역 또는 더 넓은 탐색 창에 배정한다. 시작점 주변 정밀화만으로 멀리 떨어진 미탐지 영역까지 발견된다고 가정하지 않는다. 증거가 없는 곳에 균등 배치용 대응점을 만들지 않는다.
6. **전체 변환 재추정과 비교.** 검증한 후보로 전체 사진에 하나의 similarity 변환을 추정한다. 이동·회전·균일 배율만 허용한다. 점 수나 적합에 사용한 점의 평균 오차만으로 새 결과를 채택하지 않고, 영역별 오차와 분포, 기존 결과 대비 악화를 비교한다. 서로 다른 영역이 양립할 수 없는 변환을 요구하면 불일치로 안내한다.

내부 후보 수집과 사용자에게 보여줄 추천 앵커는 구분한다. 내부에서는 여러 후보를 검증하되 화면에는 확인 가능한 수의 분산된 점만 표시한다. 자동 후보 전체를 강제 수동 앵커처럼 취급하지 않는다.

## 범위와 실행 비용

- 첫 구현 실험값: 추가 1회, 대응 크롭 4–8쌍, 패치 입력 최대 640. 이 숫자는 논문 표준이나 속도 보장이 아니라 측정 후 조정할 시작값이다.
- 추론 횟수·총 입력 픽셀·메모리 예산을 제한한다. 새로운 독립 대응이나 영역 커버리지가 늘지 않으면 조기 종료한다.
- 이미지 업로드 시 수행하지 않는다. 우선 기존 결과 안내창의 **앵커 자동 추천** 버튼을 눌렀을 때 적용한다. 마스크 없는 사진에서도 사용할 수 있게 확장한다.
- 이미지·마스크·고정상 변경에 맞춰 무효화하는 제한된 대응점/크롭 결과 캐시를 둔다. 반복 호출에서 특징 맵을 공짜로 재사용할 수 있다고 가정하지 않는다.
- 시작 후보가 전혀 없으면 이 방식 자체의 출발점이 없다. 제한된 겹침 타일 탐색이나 사용자 마스크/수동 대응으로 전환하고, 탐지하지 못했다는 상태를 명확히 표시한다.
- 마스크 없이 발견한 영역이 사용자가 비교하려는 안정적인 기준이라는 보장은 없다. 추천점 확인과 마스크를 통한 범위 지정은 계속 제공한다.
- 촬영 시점 변화나 깊이 차이 때문에 한 similarity로 모든 영역을 맞출 수 없는 경우에는 점을 늘려도 해결되지 않는다. 비율을 깨거나 비선형 변형으로 숨기지 않는다.

## UI 제안

기존 상시 안내창과 네 가지 선택지(앵커 자동 추천 / 앵커 직접 찍기 / 마스크 재선택 / 미세조정)를 유지한다. 새 팝업은 필요 없다.

- 마스크 없음: “전체 사진에서 대응 영역을 찾고 있습니다.”
- 크롭 재탐색 중: “대응 영역 N곳을 정밀 탐색하고 있습니다.” — 실제 영역 수 표시.
- 추천 생성: “추천 앵커를 확인해 주세요. 위치를 수정하거나 이 점으로 다시 맞출 수 있습니다.”
- 불충분: “신뢰할 수 있는 대응 영역이 충분하지 않습니다. 기준 영역을 선택하거나 대응점을 직접 지정해 주세요.”

이전 정합 결과를 유지한 상태에서 추천점을 미리 보고 수정한 뒤 재정합한다. 버튼을 누른 즉시 기존 결과를 교체하지 않는다.

## 구현 순서와 검증 기준

1. 원본 좌표 후보 저장소와 피라미드/크롭 좌표 역변환을 먼저 마련한다. 선행 워프 단계의 이동 마스크도 실제 이동 마스크를 같은 변환으로 옮기도록 확인한다.
2. 분산된 양쪽 원본 크롭 → 한 차례 LoFTR → 중복 제거 → 영역별 기여 제한을 구현한다.
3. 자동 추천의 무마스크 경로와 기존 안내창에 연결하고, 기존 결과와 비교할 수 있게 한다.
4. 실제 측정에서 필요한 경우에만 재탐색 반복이나 별도 매칭 모델 도입을 검토한다.

비교 실험은 같은 사진 쌍과 LoFTR 모델로 A: 현재 방식, B: 전체 입력 해상도 증가, C: 성공 영역 크롭, D: 성공 영역 크롭+미지원 영역 탐색을 비교한다. 알려진 similarity로 만든 합성 쌍과 별도 확인한 실제 사진 쌍을 나눠 평가한다.

주요 지표는 적합에 쓰지 않은 분산 검증점의 위치 오차, 영역 커버리지, 잘못된 성공 판정, 처리시간 중앙값/상위 95%, 최대 메모리다. 강한 한 영역과 약한 다른 영역, 반복 무늬, 저대비, 부분 겹침, 겹침 없음, 스케일/회전 차이, similarity로 설명되지 않는 변화, 마스크 유무를 포함한다. 점 개수만 증가하고 분포나 검증 오차가 개선되지 않으면 성공으로 평가하지 않는다.

추천: 모델 전체 교체에 앞서 **기존 LoFTR + 분산된 원본 크롭 재매칭**을 제한된 재시도 기능으로 검증한다. 적용 가능성은 근거가 있지만, 현재 앱에서의 정확도·속도 개선량은 아직 측정하지 않았다.
